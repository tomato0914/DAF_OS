## 目的

ユーザーがプライバシーポリシーに確実に同意した上でアプリを使用できる状態を作る。  
App Store / Google Play の審査要件を満たす表示フローを設計する。

---

## 1. 初回起動時の同意フロー

```
アプリ初回起動
    ↓
ウェルカム画面（スプラッシュ）
    ↓
【同意画面】← ★ここでプライバシーポリシーを提示
    ↓
    ├─ 「同意する」タップ → アカウント作成 or メイン画面へ
    └─ 「同意しない」タップ → アプリ終了（利用不可）
```

### 同意画面の要件

- [ ] プライバシーポリシーへのリンクを必ず表示する
- [ ] 利用規約へのリンクを必ず表示する
- [ ] 「同意する」ボタンは両方を確認できる状態になるまでグレーアウトする（任意）
- [ ] 「同意しない」選択肢を用意する（強制同意の禁止）
- [ ] 同意した日時をローカルに記録する

### 表示テキスト例

```
もふログをご利用いただくには、
プライバシーポリシーと利用規約への同意が必要です。

[プライバシーポリシーを読む]　[利用規約を読む]

───────────────────────────
    [同意しない]　　　[同意して始める]
```

## 2. アプリ内での常時アクセス導線

ユーザーがいつでもポリシーを確認できるように、以下の場所にリンクを配置する。

| 場所 | 表示内容 |
|------|---------|
| 設定画面 → 「法的情報」セクション | プライバシーポリシー・利用規約 |
| アカウント削除画面 | データ削除に関するポリシーへのリンク |
| App Store / Google Playのストアページ | プライバシーポリシーURL |

公開URL（確定済み）：`https://tomato0914.github.io/DAF_OS/privacy_policy`

### 実装スニペット（アプリ実装者向け・そのまま貼り付け可）

もふログアプリ側のリポジトリで、設定画面に以下のいずれかを実装してください。

**SwiftUI（iOS）**

```swift
Section("法的情報") {
    Link("プライバシーポリシー", destination: URL(string: "https://tomato0914.github.io/DAF_OS/privacy_policy")!)
    Link("利用規約", destination: URL(string: "https://tomato0914.github.io/DAF_OS/terms_of_service")!)
}
```

**React Native**

```jsx
<SettingsSection title="法的情報">
  <SettingsRow
    label="プライバシーポリシー"
    onPress={() => Linking.openURL('https://tomato0914.github.io/DAF_OS/privacy_policy')}
  />
  <SettingsRow
    label="利用規約"
    onPress={() => Linking.openURL('https://tomato0914.github.io/DAF_OS/terms_of_service')}
  />
</SettingsSection>
```

**Android（Jetpack Compose）**

```kotlin
Preference(
    title = "プライバシーポリシー",
    onClick = { uriHandler.openUri("https://tomato0914.github.io/DAF_OS/privacy_policy") }
)
```

配置基準：
- 設定画面のトップレベル、またはヘルプ/アプリ情報タブの中に「法的情報」セクションとして独立させる
- 外部ブラウザ（`Link` / `Linking.openURL` 等）で開く。アプリ内WebViewは任意（本ガイド4章の「両方（推奨）」構成に準拠）
- 既存の設定項目には手を加えず、セクションを1つ追加するだけに留める（既存UIを壊さないため）

## 3. ポリシー更新時の通知フロー

プライバシーポリシーを更新した場合、以下のフローで再同意を取得する。

```
アプリ起動
    ↓
ポリシーバージョン確認（ローカルに保存した同意バージョン vs 最新バージョン）
    ↓
バージョン不一致
    ↓
【更新通知画面】
  「プライバシーポリシーが更新されました。
   続けてご利用いただくには、新しいポリシーへの同意が必要です。」
    ↓
    ├─ 「同意する」→ 同意バージョンを更新 → 継続利用
    └─ 「同意しない」→ アプリ終了
```

---

## 4. プライバシーポリシーのホスティング方法（案）

| 方法 | メリット | デメリット |
|------|---------|-----------|
| アプリ内WebView | オフラインでも閲覧可能 | 更新のたびにアプリ更新が必要 |
| 外部URL（GitHub Pages等） | 随時更新可能 | ネット接続が必要 |
| **両方（推奨）** | 常に最新を参照しつつ、オフライン閲覧も可 | 管理コスト増 |

**推奨**：外部URLをメインとし、アプリ内にはキャッシュを持つ構成。

---

## 5. App Store提出時の必要事項

App Storeの審査には以下が必要です。

- [ ] プライバシーポリシーの公開URL（HTTPSであること）
- [ ] App Store Connectの「プライバシー - データの種類」への回答入力
  - 収集するデータカテゴリごとに用途を申告する
  - もふログの場合：「ユーザーコンテンツ（写真・記録データ）」が該当
- [ ] 「データとの紐付け」「トラッキングへの使用」の有無を申告

### App Store Connectで回答すべき主要項目

| データタイプ | 収集有無 | 紐付け | 備考 |
|------------|---------|--------|------|
| 写真またはビデオ | ○ | ユーザーアカウント | ペット写真 |
| 健康とフィットネス | ○ | ユーザーアカウント | 体重・体調記録 |
| その他ユーザーコンテンツ | ○ | ユーザーアカウント | 日常記録 |
| 識別子（ユーザーID） | ○（任意） | ユーザーアカウント | アカウント機能実装時 |
| 使用データ | ○ | 紐付けなし | 匿名の利用ログ |
| クラッシュデータ | ○ | 紐付けなし | バグ改善目的 |
